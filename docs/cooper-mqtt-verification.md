# MQTT 新闻刷新联调记录

本轮在 2026-11-04 复核当前 EMQX 与前端 MQTT v3.1.1 的连接，并使用临时 HTTP 后端验证新闻更新。未修改服务端配置、用户授权或正式新闻数据。

## 连接结果

| 项目 | 结果 |
| --- | --- |
| MQTT TCP 1883 | TCP 连接正常，原始 CONNACK 实测为 `20 02 00 00`（returnCode=0） |
| MQTT WebSocket 8083 | `/mqtt` 握手及 CONNECT 成功，SUBACK 订阅成功 |
| TCP 发布 → WS 订阅 | 临时独立主题下 QoS 1 发布/确认及消息接收成功 |
| MQTT TLS 8883 | 端口开放；默认验证因 `SELF_SIGNED_CERT_IN_CHAIN` 失败。仅在独立诊断探针中跳过证书验证后 CONNECT 成功，未在前端或生产客户端关闭证书验证 |
| 管理端 18083 | `/status` 返回 HTTP 200，EMQX running |

开发及生产环境的 `VITE_PROXY_MQTT` 已填写本次核实的浏览器 WebSocket 地址。部署目标若有自己的 Broker，应继续通过该变量配置实际地址。

## 本轮修复

1. 业务 HTTP 的 Mock 开关原本会直接跳过整个实时模块，现在显式配置 Broker 时仍建立 MQTT 连接，方便以延迟 Mock 或临时后端进行联调；日历 SSE 继续遵循原 Mock 开关。
2. 首页已存在新闻刷新监听；新闻资讯栏目列表、新闻详情原先未监听，本轮接入既有 `portalEvents`，组件卸载时移除监听。
3. 新闻详情刷新时清空相邻新闻缓存，保留既有异步请求序号、浏览计数去重及 RBAC 路由访问链路。

## 浏览器联调证据

使用真实 Keycloak/RBAC 登录、真实 EMQX TCP 发布端、真实浏览器 MQTT WebSocket 订阅端。临时后端在本机环回地址随机端口提供实际 HTTP 响应，DTO 沿用根目录 API 文档和已有延迟 Mock 数据；更新仅保存在临时进程内存。

隔离测试浏览器将业务 HTTP Mock 开关设为关闭，并把业务网关转发到临时 HTTP 后端；MQTT、身份和权限请求保持真实网络连接。没有调用前端事件发送函数代替 Broker 推送。后半程恢复浏览器原 Mock 开关，另行验证 Mock 数据与真实 MQTT 可以共存。

13 项检查通过：

- 浏览器 WS 连接及 SUBACK。
- MQTT 到达后新增新闻 HTTP 请求，首页标题实际变化。
- 公告弹窗专用 API 重新请求。
