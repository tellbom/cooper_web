# 预览权限、生产 SQL 与菜单按钮样式核查

## 结论

现有 RBAC 兼容契约和前端 `handleMenuRule` 识别的值为 `add_rules_only`。新闻预览、公告预览、Office 文档预览继续作为授权静态路由，隐藏仅作用于导航；没有权限时仍拒绝访问。

## SQL 修正与验证

- 新生产入口 `sql/cooper-production-dm.sql`：40 条规则、33 条 API 映射；不依赖 `cochain` 或其他项目，不导入测试账号，不写用户、权限组成员、项目授权或 super。
- 已有库的增量入口 `sql/cooper-preview-hidden-dm.sql`：只调整三个预览规则的隐藏属性、Link 类型和静态地址。先检查三个节点齐全，再在单事务中写元数据及对应 MenuChanged Outbox；重复执行无变更不新增事件。
- Outbox 从数据库实际记录读取 ruleGuid；规则、映射和事件显式填写创建时间，避免依赖环境默认值。
- 旧初始化存在其他项目数据依赖及测试用户替换参数，已标记历史用途；正式导入请依照 `sql/README.md` 选择新入口，不混跑旧授权脚本。

指定 DIsql 已在带唯一索引的隔离临时表验证：全新导入为 40/33/73（规则/映射/事件），再次执行不变；模拟三个节点的错误标识和旧 Tab 配置后，增量修正新增 3 条事件，再次执行不变；缺少节点时先报错，未继续更新。临时表已清理。

当前开发数据库已执行三个预览节点增量修正，回读为 `add_rules_only + Link + /preview/...`。执行前后的用户组权限内容、成员和项目授权记录逐项一致。正式内网数据库尚未执行。

浏览器 12 项预览验收通过：真实 RBAC 返回三个隐藏节点、全部导航排除这些节点；三个预览都可正常打开并刷新；隔离浏览器中移除对应颁发节点后，三条路径均进入 401。正向使用真实 RBAC，负向仅修改隔离测试浏览器的响应，不修改用户授权。

## 两处截图的样式根因

1. 门户将子菜单标题左右 padding 压缩为 10px，而 Element Plus 箭头仍绝对定位，长文字与箭头区域重叠。现在箭头进入标题正常排列，保留独立间距，旋转动画仍由组件控制。
2. 门户的通用 `button` 重置带有容器选择器，优先级高于 Element Plus 默认按钮样式，导致内边距被清零。现在重置排除 `.el-button` 及分页按钮，由已有组件负责按钮内边距和状态，保留原生门户按钮样式。

浏览器 12 项样式验收通过：顶部子菜单箭头、API 映射页面与抽屉、管理员、权限组、菜单规则、项目授权、应用中心、值班弹窗、分页、1366px 宽度及运行时错误。截图所示“新增映射”的左右内边距恢复为 15px，搜索按钮为 20px。未引入新的 UI 库或变更框架版本。
